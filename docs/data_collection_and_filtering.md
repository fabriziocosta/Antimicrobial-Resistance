# Data Collection and Filtering Process

This document describes how the active workflow builds AMR publication signals from PubMed and filters them into pair-level yearly datasets.

The active entrypoint is `notebooks/04_collect_yearly_data.ipynb`. The implementation lives mainly in:

- `amr.pipelines.collection`
- `amr.pubmed.intervals`
- `amr.pubmed.search`
- `amr.pubmed.yearly`
- `amr.screening`

## Overview

The pipeline intentionally separates broad retrieval from strict interpretation.

1. Broad PubMed searches collect candidate papers for pathogen-antibiotic pairs.
2. PubMed publication metadata converts interval-level PMID lists into yearly pair counts.
3. Background publication counts are collected for the pathogen and antibiotic marginals used by SI modeling.
4. A unified LLM pass reviews each `(PMID, pathogen, antibiotic, year)` candidate using the title and abstract.
5. Screened yearly pair counts are rebuilt from LLM decisions.

The search stage is recall-oriented. The LLM stage is the pair-specific relation and relevance filter.

## Inputs

The collection notebook expects:

- `assets/counts_extended2.csv`: ranked human bacterial pathogen list from Zenodo, ordered by `pathogenic_index`.
- `assets/bacteria_synonym_lookup.csv`: broad pathogen synonym mapping used only for PubMed query expansion.
- `assets/antibiotic_list3.xlsx`: source workbook for canonical antibiotic names, spelling variants, and category metadata.
- `assets/antibiotic_synonym_lookup.csv`: antibiotic synonym table generated by `notebooks/01_prepare_inputs.ipynb`.
- `assets/antibiotic_coarsening_lookup.csv`: antibiotic class/category table generated by `notebooks/01_prepare_inputs.ipynb`.
- A PubMed contact email for Entrez.
- Optional LLM credentials for the unified abstract screen.

Important notebook controls:

- `TOTAL_START_YEAR`, `TOTAL_END_YEAR`: full intended corpus window.
- `SLICE_START_YEAR`, `SLICE_END_YEAR`: current resumable run slice.
- `INTERVAL_YEAR_GAP`: PubMed pair-search interval size.
- `MIN_PATHOGENIC_INDEX`: lower bound for the Zenodo pathogen list; the notebook currently keeps rows with `pathogenic_index > 0`.
- `NUM_PATHOGENS`, `NUM_ANTIBIOTICS`: prefix limits on the pathogenicity-ranked pathogen list and sorted antibiotic vocabulary for the current run.
- `EXTRA_AMR_KEYWORDS`: broad AMR keyword constraint applied during pair retrieval.
- `PAIR_FULL_FETCH_THRESHOLD`: if pair total count is below this value, fetch all pair PMIDs once and partition locally.
- `BACKGROUND_SCOPE`: `observed_entities` for fast runs, `all_entities` for full canonical background coverage.
- `LLM_CATEGORY_BACKFILL_DECISIONS`: which old decisions should be reprocessed when new category columns are missing.

`NUM_PATHOGENS = None` or `NUM_ANTIBIOTICS = None` means use the full active vocabulary. Setting explicit values such as `NUM_PATHOGENS = 5` and `NUM_ANTIBIOTICS = 5` processes only the first `5 x 5` Cartesian grid for that run. For pathogens, "first" means highest `pathogenic_index` first.

## PubMed Candidate Collection

The notebook first loads the ranked Zenodo pathogen table and antibiotic vocabulary, then derives the active run lists. The broad synonym table is still loaded, but it is used to expand PubMed query terms for each selected pathogen rather than to define the pathogen run list.

```text
pathogen_priority_df = read counts_extended2.csv
pathogen_priority_df = rows where pathogenic_index > MIN_PATHOGENIC_INDEX
pathogen_priority_df = sort by pathogenic_index descending, then CanonicalSpecies ascending
all_pathogens = pathogen_priority_df.CanonicalSpecies
all_antibiotics = sorted full antibiotic vocabulary

pathogens = all_pathogens[:NUM_PATHOGENS] if NUM_PATHOGENS is not None else all_pathogens
antibiotics = all_antibiotics[:NUM_ANTIBIOTICS] if NUM_ANTIBIOTICS is not None else all_antibiotics
```

For each active pathogen-antibiotic pair, the pipeline first determines which date intervals are missing from `pmids_results.parquet`.

The active pair keys are always canonical names:

- pathogen: `CanonicalSpecies` from the Zenodo-ranked pathogen list
- antibiotic: `Antibiotic` from `antibiotic_coarsening_lookup.csv`

PubMed queries expand those canonical keys with synonyms:

- pathogen clauses use `bacteria_synonym_lookup.csv`
- antibiotic clauses use `antibiotic_synonym_lookup.csv`

The expanded terms only affect retrieval. Cached outputs, LLM rows, yearly counts, background counts, and SI modeling continue to use canonical pathogen and antibiotic names.

If all intervals for a pair are already cached, no PubMed query is made for that pair. Otherwise, the pipeline performs one total-window pair query:

- If total count is zero, all missing intervals are written as zero-count rows.
- If total count is below `PAIR_FULL_FETCH_THRESHOLD`, all PMIDs are fetched once and partitioned into intervals using PubMed publication dates.
- If total count is high, each missing interval is queried directly, with recursive splitting for PubMed result-limit cases.

This means the current implementation does use the main speed trick from the archived workflow: query once, fetch once, partition locally whenever possible.

Expanding from `NUM_PATHOGENS = 5`, `NUM_ANTIBIOTICS = 5` to `NUM_PATHOGENS = 10`, `NUM_ANTIBIOTICS = 10` revisits the larger `10 x 10` grid, but cached rows for the original `5 x 5` grid are skipped. Only newly introduced pair-interval combinations are queried.

### Candidate Collection Pseudocode

```text
load full pathogen and antibiotic vocabularies
apply NUM_PATHOGENS and NUM_ANTIBIOTICS prefix limits
load existing interval cache from pmids_results.parquet
build date intervals for MIN_DATE..MAX_DATE

for canonical_pathogen in pathogens:
  pathogen_terms = canonical_pathogen plus bacteria synonyms

  for canonical_antibiotic in antibiotics:
    antibiotic_terms = canonical_antibiotic plus antibiotic synonyms and split slash/hyphen variants
    missing_intervals = intervals not already cached for this pair

    if no missing_intervals:
      continue

    total_query = PubMedSearch(pathogen_terms, antibiotic_terms, MIN_DATE, MAX_DATE, AMR_keywords)
    total_count = total_query.count

    if total_count == 0:
      for interval in missing_intervals:
        write interval row with pmids=[], count=0
      checkpoint cache
      continue

    if total_count <= PAIR_FULL_FETCH_THRESHOLD:
      all_pmids = retrieve all PMIDs for total_query
      metadata = fetch publication date and venue for all_pmids

      for interval in missing_intervals:
        interval_pmids = PMIDs whose publication date falls inside interval
        write interval row with canonical_pathogen, canonical_antibiotic, interval_pmids, count, venue histogram
      checkpoint cache
      continue

    for interval in missing_intervals:
      interval_query = PubMedSearch(pathogen, antibiotic, interval.start, interval.end, AMR_keywords)
      interval_pmids = retrieve interval PMIDs, recursively splitting if result count is too high
      metadata = fetch publication date and venue for interval_pmids
      write interval row with filtered interval_pmids, count, venue histogram
      checkpoint cache
```

## Yearly Pair Counts

The interval cache is exploded to one row per `(pathogen, antibiotic, PMID)` association. Publication metadata is fetched only for new pair-PMID associations not already present in `candidate_amr_pair_pmid_links.parquet`.

The enriched rows are aggregated by publication year:

- `candidate_amr_pair_pmid_links.parquet`: one row per candidate pair-PMID association.
- `pubmed_pmid_metadata.parquet`: PMID-level publication date and venue cache.
- `candidate_amr_pair_year_counts.parquet`: yearly unscreened candidate counts by pathogen-antibiotic pair.

### Yearly Aggregation Pseudocode

```text
interval_df = read pmids_results.parquet
pair_pmid_raw = explode interval_df.pmids into pair-PMID rows

existing_pair_pmids = read candidate_amr_pair_pmid_links.parquet if it exists
new_pair_pmids = pair_pmid_raw minus existing_pair_pmids
write merged pair-PMID cache

metadata = fetch missing PubMed metadata for new_pair_pmids
enriched = attach pub_year and venue to new_pair_pmids
yearly_delta = group enriched by pathogen, antibiotic, pub_year

existing_yearly = read candidate_amr_pair_year_counts.parquet if it exists
candidate_amr_pair_year_counts = union PMID lists per pathogen, antibiotic, year
write candidate_amr_pair_year_counts.parquet
```

## Background Counts

Background counts estimate general publication attention for each pathogen and antibiotic independently. These are used later for scientific-interest normalization.

Two modes are supported:

- `observed_entities`: count only pathogens and antibiotics that appear in `candidate_amr_pair_year_counts.parquet`. This is faster and suitable for iterative runs.
- `all_entities`: count the full configured pathogen and antibiotic vocabulary. This is more complete but much slower.

The count implementation avoids year-by-year queries when possible. It queries a missing year window, fetches all PMIDs when the count is below `BACKGROUND_FETCH_THRESHOLD`, and partitions counts locally by publication year.

### Background Count Pseudocode

```text
if BACKGROUND_SCOPE == "observed_entities":
  background_pathogens = unique pathogens in candidate_amr_pair_year_counts
  background_antibiotics = unique antibiotics in candidate_amr_pair_year_counts
else:
  background_pathogens = all configured pathogens
  background_antibiotics = all configured antibiotics

for each entity:
  identify missing years in existing background cache
  merge adjacent missing years into windows

  for each missing window:
    count = PubMedSearch(entity_clause, window).count

    if count == 0:
      write zero for every year in window
    else if count <= BACKGROUND_FETCH_THRESHOLD:
      pmids = retrieve all PMIDs for window
      metadata = fetch publication dates
      count PMIDs by publication year locally
      write yearly counts
    else:
      split window into smaller windows and repeat
```

## Unified LLM Filtering

The LLM screen runs at the reviewed combination level:

```text
(PMID, pathogen, antibiotic, year)
```

This is important because a single PMID can be relevant for one pathogen-antibiotic pair and irrelevant for another.

For each candidate row, the pipeline fetches or reuses cached PubMed title/abstract text. The LLM receives:

- target pathogen
- target antibiotic or antibiotic class
- title
- abstract

The LLM returns JSON with:

- `decision`: `strict`, `yes`, `no`, or `uncertain`
- `primary_category`: SI-driver category
- `rationale`
- `evidence_phrases`
- `target_pair_relation_supported`
- `is_amr_relevant`

`strict` means the abstract explicitly links the target pathogen to the target antibiotic/class. `yes` means the pair is supported more broadly by an AMR-relevant panel, class, or shared study context. Unsupported target-pair relations are treated as `NONE`.

Rows without abstracts do not call the LLM. They receive deterministic `uncertain` / `NONE` defaults.

### LLM Filtering Pseudocode

```text
candidate_df = explode candidate_amr_pair_year_counts into one row per PMID, pathogen, antibiotic, year
resume_df = read yearly_amr_unified_decisions.parquet if it exists

for existing decision rows:
  if all AMR category columns exist:
    mark row complete
  else if category_backfill_decisions is set and row decision is not in that set:
    defer category backfill and keep row as-is
  else:
    requeue row for LLM category backfill

prefetch missing abstracts for rows that are not complete

for candidate row:
  if row is complete:
    skip

  title, abstract = abstract cache lookup or PubMed fetch

  if abstract missing:
    write uncertain weak-signal default row
    continue

  prompt LLM with target pair, title, abstract
  parse JSON
  normalize decision and category fields
  write reviewed row

checkpoint decisions, abstract cache, and failure retry state periodically
```

## Screened Yearly Dataset

The final screened yearly dataset is rebuilt from LLM-reviewed candidate rows.

By default, `build_yearly_screened_pairs(...)` includes:

- `strict`
- `yes`

and excludes:

- `no`
- `uncertain`

The default keeps accepted AMR evidence while leaving missing-abstract or technical-failure `uncertain` rows out of downstream SI modeling.

### Screened Dataset Pseudocode

```text
yearly_candidates = explode candidate_amr_pair_year_counts.pmids
reviewed_keep_keys = unified decisions where decision in {"strict", "yes"}

filtered = yearly_candidates inner join reviewed_keep_keys
deduplicate by PMID, pathogen, antibiotic, year

yearly_screened = group filtered by pathogen, antibiotic, year:
  count = number of unique PMIDs
  pmids = sorted unique PMIDs

write yearly_amr_screened_pairs.parquet
```

## Main Outputs

- `pmids_results.parquet`: interval-level broad PubMed pair results.
- `candidate_amr_pair_pmid_links.parquet`: exploded candidate pair-PMID associations.
- `pubmed_pmid_metadata.parquet`: PMID publication metadata cache.
- `candidate_amr_pair_year_counts.parquet`: unscreened yearly candidate pair counts.
- `pathogen_tiab_counts.parquet`: pathogen background counts.
- `antibiotic_tiab_counts.parquet`: antibiotic background counts.
- `pmid_abstracts.parquet`: title/abstract cache.
- `yearly_amr_unified_decisions.parquet`: LLM decision and category table.
- `yearly_amr_screened_pairs.parquet`: screened yearly pair counts used by SI modeling.

## Practical Run Modes

For fast iteration:

```text
NUM_PATHOGENS = 5
NUM_ANTIBIOTICS = 5
BACKGROUND_SCOPE = "observed_entities"
PAIR_FULL_FETCH_THRESHOLD = 9500
LLM_CATEGORY_BACKFILL_DECISIONS = ("strict", "yes", "uncertain")
```

For a fuller canonical refresh:

```text
NUM_PATHOGENS = None
NUM_ANTIBIOTICS = None
BACKGROUND_SCOPE = "all_entities"
PAIR_FULL_FETCH_THRESHOLD = 9500
LLM_CATEGORY_BACKFILL_DECISIONS = None
```

The fast mode is usually appropriate during exploration because it avoids full-vocabulary background counts and avoids spending LLM calls categorizing old `no` rows.
